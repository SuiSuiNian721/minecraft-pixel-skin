# 建立或修正模板

## 来源和目录

读 `assets/templates/index.json`。原图字母/编号优先；无编号的装饰分组按从左到右、从上到下登记，不凭图猜名字。当前目录涵盖眼睛 3、耳朵 9、角/尾巴/翅膀 9、眼镜/眼罩 6、帽子/光环 9。

有原始 64×64 PNG 时用 `skin_tools.py inspect` 精确读取面与层；有指南效果图时只重建可见结构，并记录被遮处的补全决定。`assets/sources/reference_xiaoli.png` 是精确读取的回放样本，`guide.png`/`guide-eyes.png` 是指南来源。`assets/sources/guide-eyelashes-detail.png` 为用户补充眼缘参考的只读副本；`guide-bc-detail.png` 是指南 B/C 示例刘海细节，不能作为所有 B/C 角色的发型要求。所有原始参考只读。

## 母版数据

以 `assets/templates/index.json` 指向的模板 JSON 为权威像素数据，PNG 补丁和展示图由它生成。正式制作读取目录指向的 `versions/1.0.0.json`；原 `template.json` 保留为历史候选，仅用于候选审阅和来源追溯。

| 字段 | 含义 |
| --- | --- |
| `id` / `version` | 稳定编号与版本；改变结构时新建版本，保留历史角色采用的版本 |
| `models` | 支持的 Slim/Classic；手臂宽度不同，不能自动混用 |
| `provenance.kind` | `exact_png`、`reconstructed_from_guide` 或 `authored` |
| `approval.status` | `pending`、`approved` 或仅作样本的 `reference_only` |
| `palette` | 颜色键 → `rgba` 与 `role`；结构和具体角色配色分开 |
| `required_palette_bindings` | 使用者必须显式绑定的颜色键；A/B/C 眼型模板不含头发颜色或强制 `H` 绑定 |
| `surfaces` | 每个涉及面的 `base`、`outer` 矩阵；行字符串或二维 token 数组 |
| `protected_visible` | 同面局部坐标的默认可见要求；标记 iris/sclera/eyelid 等用途，参考明确要求的遮挡另记精确例外 |
| `allowed_alpha` | 明确允许的外层半透明位置和 Alpha 值 |
| `reconstruction_decisions` | 效果图无法确定、由重建决定的部分 |

矩阵以左上角 `(0,0)` 为起点。`.` = KEEP；`-` = CLEAR，仅用于外层；其他 token = 指定调色板颜色。基础面补丁可留 KEEP，但完整皮肤的有效基础面必须不透明。

A/B/C 的外层全部 KEEP，保留源角色的头发与配饰。基础层 y=4 的 x=1、6 可能是上眼缘，被刘海遮住不代表属于头发。先逐格识别当前源图：替换已确认的旧眼部，保留实际发丝；不能把固定坐标一律 KEEP 或恢复肤色，冲突通过角色变体处理。保护区检查意外遮挡，允许参考中的刘海部分遮住延伸眼缘，外眼角不要求对应外层全透明；额外遮眼须记录依据与准确例外。模板冲突要定位到像素，不能靠绘制顺序假装增加一层。

## A/B/C 的当前候选结构

| 项目 | A | B | C |
| --- | --- | --- | --- |
| 候选版本 | `0.3.0-candidate` | `0.5.0-candidate` | `0.5.0-candidate` |
| 上眼缘 / 闭眼线 | y=4：`.LL..LL.` | y=5：`SLL..LLS` | y=6：`LLL..LLL` |
| 虹膜、眼白与外角 | y=5：`UTI..ITU`；y=6：`VWJ..JWV` | y=6：`LWI..IWL` | 不绘制虹膜或眼白 |

`L` 为深色眼缘，`S` 用于清理已识别的旧眼部像素；遇实际发丝冲突采用角色变体。A 的 `U/V` 分别为外眼角上、下两段颜色，按当前角色参考独立配色，不全随 `L` 染黑。指南可见的是上眼缘与外眼角围边，没有完整闭合黑圈的证据。外层刘海遮住部分底层后会只露出窄条；隐藏处的延续是重建候选，不能声称从指南精确提取了底层。小璃原始 PNG 可支持围边结构的合理性，但不能证明指南隐藏像素与其相同。

以上是眼型候选坐标，来源不是作者原始 UV，也不是整张人脸构图的硬约束。发型变化不等于改变通用眼型模板：角色的发型形状、发长、分缝、刘海和配饰按当前参考重建。眼睛占位与参考要求的基础层发丝冲突时，制作当前角色的眼型变体或局部遮挡，列明具体变化格与参考依据后锁定，无需重新批准整个通用模板。只有修改供其他角色复用的通用眼型结构时，才按母版版本规则发布新版本。

## 指南发型示例

指南 A/B/C 可分别加载独立发型 fixture：A 的 `assets/fixtures/guide-a-hair.json` 在正脸外层 y=4、x=1、6 绘制遮住部分上眼缘的刘海，y=7、x=0、7 绘制外侧发梢；B/C 的 `assets/fixtures/guide-bc-hair.json` 在 x=1、6，y=4–5 绘制内收刘海，x=1、6，y=7 绘制内收发梢。这些坐标只解释各自指南示例，不属于通用眼型矩阵。

各示例卡在含 `project.fixture` 的审阅项目中，通过 `card.example_overlays` 显式引用对应发型；其值为相对 Skill 根目录的路径字符串数组，示例发色由 fixture 提供。角色 `source` 项目禁止使用此类示例 overlays，不能把示例发型或测试发色带入当前角色。

## 审阅与冻结

1. 用共同头模、配色和镜头比较眼型。需要复现指南 B/C 发型时显式加载独立示例 overlay，说明哪些像素来自眼型、哪些来自示例发型。
2. 每个涉及面输出「基础层 / 外层 / 同坐标叠加」，附坐标和调色板；头发跨到侧、顶、后面时必须展示那些面。
3. 查看实际立体正面、左右斜侧面、必要的顶/后视图，以及外层关闭效果。图上的同坐标透明不保证所有视角都没有遮挡。
4. 做换色与组合检查，报告像素变化范围。半透明镜片只允许声明区域，目标游戏环境另行验证。
5. 用户确认候选后记录确认依据、日期、模板版本、像素哈希与验证范围，再把状态改为 approved。目录版本与模板版本同步。此后不原地重写已供角色引用的模板。

动效、额外几何与特殊客户端支持不属于静态 PNG 母版的既定能力。只有实际验证的效果才能标为可交付。
