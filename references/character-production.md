# 制作或修改角色

## 选型与配色

确认当前权威 PNG/设定图、Slim 或 Classic、眼型与部件编号、发型形状、发长、分缝、刘海、配饰左右和必须保留的特征。发型始终依据当前角色参考，不能由 A/B/C 眼型编号推定。沿用用户已做的选择；真正缺失且会改变外观的选择集中确认一次。可明确推荐，但不把推荐写成用户已选。

查模板目录的状态与版本。未重建部件不能冒充可用模板；待确认母版可以在用户已授权的候选制作中使用 `--purpose review`，不会因此自动批准母版。

把眼型颜色按用途绑定：肤色、眼白、虹膜深/浅、眼缘。A 的外眼角上、下两段 `U/V` 按当前参考独立配色，不全随眼睑 `L` 染黑。A/B/C 不包含头发颜色或 `H`；头发单独制作与配色，外层 KEEP 保留现有发型，不套用指南示例刘海或测试发色。

例如小璃参考的粉瞳深/浅为 `(218,90,123,255)` / `(252,167,195,255)`，仅作为配色示例。实际使用前读取当前参考确认，不能跨人物沿用。

## 实作

1. 记录源文件哈希，新建候选路径。`skin_tools.py inspect` 可提取任何涉及面的逐格数据。
2. 读取当前候选的上眼缘、虹膜/眼白和外眼角坐标，见 [模板制作](template-authoring.md)。`.` 保留源图；A/B/C 外层全部 KEEP。基础层先逐格识别旧眼部和实际发丝：y=4 的 x=1、6 也可能是眼缘，不能因它被刘海遮住就固定保留为头发，也不能无条件恢复肤色。只替换确认的旧眼部，保留实际发丝及无关区域。
3. 按当前参考适配发型。眼型绘制位置与参考要求的基础层发丝冲突时，制作当前角色变体或局部遮挡，不能把 A/B/C 坐标当成人脸全部构图的硬约束。先明确具体变化格与依据再锁定，并输出头部基础层、外层、叠加和立体效果。普通角色适配不要求重新批准整个通用模板；已有对应确认继续有效。改变供其他角色复用的通用眼型结构时，再按母版版本规则处理。
4. 完成服装和背面，保持确认的头部。短发不继承旧角色的长发或胸前发束。检查肩、领口、身体侧面、裙摆/腿等交界。
5. 组合刘海或配饰后检查保护区。允许头发部分遮住底层延伸眼缘，外眼角不要求对应外层全透明。额外遮眼须记录参考依据、准确区域及已有选型/授权，用 `--exceptions` 保留设计，不自动剪发或全局关掉检查。半透明另用 `--allowed-alpha` 声明区域与数值；两者均可在 `compose` 时传入，格式与 `validate` 相同。
6. 核对输出像素、Alpha、UV、模型、变化坐标、源文件哈希与 PNG 回读。立体查看后分别报告文件检查、预览器检查及游戏内检查结果。

只要求改两格时，其余 4094 格应保持一致。若要求改变整个眼型，实际变动以模板操作范围为准，不承诺只改虹膜。颜色量化、滤镜和整图重新生成均不能越过已锁定区域。

## 交付

交付新版本原生 PNG、相关面的分层图、模型预览、模板版本/配色/验证清单。明确这是候选还是已确认成品。没有游戏内验证就直说；不要将浏览器显示正常写成已经在目标游戏成功应用。

`render_review.py` 支持用共同 fixture 比较母版，也支持项目 JSON 中的 `source` 指向当前角色，生成单个或多个模板候选。`card.example_overlays` 仅供含 `project.fixture` 的示例审阅项目使用，角色 `source` 项目禁止加载指南发型示例。工具命令和最小项目示例见 [工具与验证](tools-and-validation.md)。
